# AGENTS.md

## Repository layout

- Two independent npm apps; there is no root `package.json`, workspace, or CI workflow. Run installs/scripts inside `client/` or `server/` using npm.
- `client/`: Next.js 16 App Router frontend with Tailwind CSS v4 and the Better Auth React client.
- `server/`: Express 4 API using the native `mongodb` driver (no Mongoose) and Better Auth.
- Most server route modules export a `create*Router(deps)` factory used by tests plus a default router wired to production middleware/collections. Mount new routers explicitly in `server/src/routes/index.ts`.
- Collections: `studios`, `users`, `sessions`, `accounts`, `verifications`, `bookings`, `saved_studios` (wishlist; not `wishlists`), `host_applications`. Model helpers create indexes lazily on first use.

## Commands

No client test suite and no CI. Verify server changes with typecheck/test/build and client changes with lint/build. The server has no lint script.

### Server (`server/`)

- `npm run dev` — start with `tsx watch`
- `npm run typecheck` — `tsc --noEmit` (compiles only `src`; `test/` is excluded, so test type errors are not caught)
- `npm test` — offline `node:test` suite using injected fake collections; no MongoDB or `.env` needed
- Run one test: `node --import tsx --test test/studio.route.test.ts`
- Add new test files to the explicit `test` script in `server/package.json`; they will not run otherwise.
- `npm run build` — compile to `dist/` (ignored); `npm start` runs the compiled server
- `npm run seed:studios` — needs a live database; upserts an idempotent 24-studio demo catalog. `test/demo-studios.test.ts` enforces exactly 24 studios, 6 each in photography/film/podcast/music, unique images/hosts, and booking terms.
- Relative imports in server TypeScript use `.js` extensions (NodeNext), including imports of `.ts` files.

### Client (`client/`)

- `npm run dev` — start the Next.js dev server
- `npm run lint` — run ESLint (flat config)
- `npm run build` — intentionally uses `next build --webpack`; keep the Turbopack CSS loader setup in `next.config.ts`
- Before editing client code, read `client/AGENTS.md` and the relevant guide under `client/node_modules/next/dist/docs/`. Next 16.4.6 has breaking changes versus older training data; `params`/`searchParams` are Promises and `cacheComponents` is enabled. `client/AGENTS.md` is regenerated by `next dev`; keep it committed.
- Baseline currently fails on uncommitted dashboard work: `npm run lint` reports `react-hooks/set-state-in-effect`, and `npm run build` type-checking fails where dashboard pages use `Studio.id`/`Studio.pricing` instead of `_id`/`pricePerHour` (see `client/src/lib/studios.ts`). Check whether a failure is pre-existing before treating it as yours.

## Environment and runtime

- Copy `server/.env.example` to `server/.env`. `MONGODB_URI` and `BETTER_AUTH_SECRET` (32+ characters) are required. `MONGODB_DATABASE` defaults to `studiospace`, `PORT` to `5000`, `CLIENT_URL` is the trusted browser origin, and `BETTER_AUTH_URL` defaults to `http://localhost:<PORT>`.
- Start the server from `server/`: `dotenv.config()` loads `.env` from the process working directory.
- Importing `server/src/index.ts` immediately connects to MongoDB and calls `initAuth()`, exiting the process on failure. `NODE_ENV=test` only skips `app.listen()`; the DB connection still runs, so do not import the entrypoint in tests.
- Better Auth is mounted at `/api/auth/*` before `express.json()` so it receives the raw request stream; preserve that ordering. Auth users live in `users` with `role: "renter" | "host" | "admin"`; sessions/accounts/verifications are separate collections.
- CORS uses `credentials: true` and allows only `CLIENT_URL`, plus localhost/127.0.0.1/LAN origins when `NODE_ENV=development`. Browser API calls must send `credentials: "include"`.
- `client/.env` is optional; set `NEXT_PUBLIC_API_URL` only when the API is not on port 5000 of the same host.

## Server conventions

- Keep route handlers async with explicit `try/catch`; log internal errors server-side and return generic `500` responses.
- All resource IDs are 24-character ObjectId strings. Validate before `new ObjectId(...)` and return `400` for malformed IDs.
- Auth chain: `requireAuth` (sets `res.locals.authUser`) → `requireRole(...)` → `requireStudioOwner` where applicable. `requireStudioOwner` permits the owner or an admin. Never trust `hostId`, user IDs, prices, or ownership from the request body; derive them from the session or database.
- Studio POST requires `host`/`admin` and creates `status: "draft"` (seeded studios are `published`). PUT rejects protected fields (`hostId`, `_id`, `status`, `createdAt`, `updatedAt`) with `400` and updates only whitelisted fields.
- Bookings calculate duration/price server-side from the studio record and reject overlapping `pending`/`confirmed` bookings with `409`. Host-application approval promotes the applicant's `users.role` to `host`.
- Use model helpers (`getStudioCollection`, `createStudioDoc`, etc.) and whitelist request fields instead of passing `req.body` through.

## Client conventions

- Never read `process.env.NEXT_PUBLIC_API_URL` directly; use `API_URL`/`getApiBaseUrl()` from `client/src/lib/apiUrl.ts`. Without env it targets `<current hostname>:5000` in the browser and `localhost:5000` during server-side fetch.
- Use the typed helpers in `client/src/lib/` for API calls and keep `credentials: "include"` on authenticated requests. The server returns `studio` with `_id`; normalize it as the existing helpers do.
- App Router entrypoint is `client/src/app/page.tsx`; shared layout is in `layout.tsx`. The `@/*` alias maps to `client/src/*`.
- Reuse the Tailwind v4 theme tokens defined in `globals.css` (`bg-surface`, `text-accent`, etc.) and the primitives in `src/components/ui/` rather than adding one-off colors. The theme is a `data-theme` attribute (`dark` default) set before paint by `src/lib/theme.ts`.
- Remote images are allowlisted to `images.unsplash.com` in `next.config.ts`; update that list before using another host.
